# SNHU, CS-250, Software Development Lifecycle
## Module Eight Journal - Portfolio Item

1. How do I interpret user needs and implement them into a program? How does creating "user stories" help with this?

   I would interpret user needs by focusing on the problem behind what is needed by the user. I can then break those down into specific, actionable requirements. User stories help this process because it provides those needs in a simple format: the role, the goal, and the benefit. It makes it easier to design, code, and test features that solve real-world poroblems. 
  
2. How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

   My approach to developing programs would be breaking the big problems into smaller, manageable chunks. I would start by identifying the core functionality then expand upon that work using iterative developments. Doing these things would help avoid the overwhelming feeling that comes with working on complex issues and it helps to ensure that I always have something to work on.

   In terms of Agile processes that I would incorporate, I would want iterative development, so I can provide incremental updates rather than doing it all at once. I would also encourage the continuous feedback loops so any necessary changes can be made before problems become more significant.

4. What does it mean to be a good team member in software development?

   Being a good team member in software development means balancing contribution with collaboration. From the contribution side, I would need to write clear, maintainable code. Depending on my role, that might also include reviewing the code of my peers, constructively. From the collaboration side, I would need to communicate openly, ask for help when needed, and support my teammates.

   It also means being reliable. I can do that by meeting my commitments and being flexible and adaptable when priorities change.
